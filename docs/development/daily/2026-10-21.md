## 推荐方案与备选

**推荐 A：镜像 + 隔离完整编排 + 明确使用测试依赖的启动烟测，预计 6–9 小时。** 延续已完成的阶段 1A，进入阶段 1B；与昨日最大的变化是 Docker 在常规环境已可连接，不再因旧阻碍跳过运行验收。JD 索引给出的工程闭环方向只作弱佐证，具体范围由已核实启动依赖决定。

1. Python 3.12 镜像安装锁定运行依赖和 wheel，非 root 运行；API/worker 共镜像，入口分别是 uvicorn 与现有 worker main。只保留运行资源，明确排除 .env、.git、数据、缓存、node_modules 及本地产物。
2. Node 22 多阶段构建 Next standalone；只把公开 API URL 作为 build 参数，本机默认指向回环地址。保持现有开发体验，按指南携带静态资源，不更换构建器或 UI。
3. 在 ops 建独立 Compose，不叠加根文件里的固定容器名和旧卷。DB 健康 → 一次性迁移 + 基础 SKU seed → API/可选 worker；Milvus 依赖显式。仅回环绑定测试端口，单实例 worker 置于显式 profile，普通启动不自动消费数据或调用模型。
4. 专用 smoke profile/覆盖文件使用测试 embedding HTTP 服务，按真实协议返回 1024 维，明确是假依赖；不修改生产启动检查。覆盖健康/登录/空仪表盘、重复 init、init 失败阻断、768 维拒绝启动、web 静态资源及浏览器可用 URL。测试网络限制外部模型调用。结果只称“真实容器 + 测试 provider 的启动烟测”，不称真实模型/Ask 效果验收。

取舍：先用本机公开 URL 构建前端，不在今天增加网关、运行时 URL 注入或生产 CORS 方案。代价是更换演示域名时需要重新 build；以后上线设计再讨论同源代理。worker 镜像和编排入口交付，但默认不开启；不新增 Celery、Redis、Kubernetes 或 Agent 框架。依赖镜像/包下载和资源不足仍可能增加排障时间，不保证一晚完成全部范围。
