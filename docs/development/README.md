# 每日工程开发入口

目标：将 VOC Agent 建设为面向 Python 后端、AI 应用、AI 全栈校招的完整工程项目，最终支持在线演示。

## 工作方式

- 每天北京时间 12:00 独立运行定时任务 `voc-agent`，生成当天规划，在该次新聊天讨论决策，不返回原始配置聊天。
- 自动运行先做调研、仓库检查和规划落盘；用户在新聊天明确确认方案后，才开展对应开发、提交与推送。
- 本地任务需要电脑开机、桌面应用运行、仓库可访问。定时开始不代表规划会在 12:00 前完成。
- 跨聊天通过本目录交接；以代码和实际验证为准，历史测试成绩不当作本次运行结果。

## 阅读顺序

1. [status.md](status.md)：当前状态、阻碍和进行中的工作。
2. [roadmap.md](roadmap.md)：阶段方向和验收标准。
3. [backlog.md](backlog.md)：候选任务与优先级。
4. `daily/` 最近日志和 `decisions/` 已确认决策。
5. 实际代码、适用 AGENTS.md、git 状态和近期提交。

## 写入约定

每日按 旧模板 `templates/daily.md` 创建 `daily/YYYY-MM-DD.md`，日期取北京时间。同日重跑保留原内容和确认记录，追加更新；旧日志不改写为新状态。每日日志记录快照，其余三个索引文件维护最新状态。

调查必须记录来源、访问日期、可信边界及实际借鉴点。动态页面不可读、岗位类别不明、未确认仍在招时如实标注。调研失败仍可基于已核实仓库事实制定计划。

开发确认后记录范围；重大架构选择使用 `decisions/NNNN-topic.md`，包括背景、备选、确认结果和后果。开发每个有意义的增量结束或暂停、受阻时，都回填每日文档并更新索引，避免只在顺利完成时记录。

提交以独立、有效、可验证为边界，每天争取 4–5 个；不得通过空提交和无意义拆分凑数。记录完整 SHA、推送状态、验证命令和实际结果。只处理本次改动，保护其他聊天和用户工作，不提交密钥及本地运行产物。

原始背景见 原始计划 `docs/career_engineering_plan.md`；后续最新状态以本目录为入口。
