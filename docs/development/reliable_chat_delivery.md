# VOC 对话可靠性修复交付

## 产品行为

生产 `/api/ask` 使用 `ReliableVocRouter` 处理当前支持产品的常见分析请求。评论数、情绪分布、方面分布、ISO 周趋势和同档比较直接按结构化工具结果呈现，明确评论/提及的分母及系统归档范围，避免模型改写数字和日期。统计服务不需要等待聊天模型生成。

定性回答采用可追溯原文；续航案例保留负载、使用时间和剩余电量条件。能从明确原文提取的数值才生成中文摘要，不把充电速度、重量或某一工况换算成统一续航。来源明确写 DELTA Max/Pro 等其他型号时，排除该体验引用并提示归属待核实。

原文明确提出改进意见而归档为正面时，展示“情绪标签待复核”，不将它用作好评样例。统计仍按现有归档标签计算并说明限制；没有静默改写源评论或产品归档。

未知产品先核对目录，缺少数据说明查询范围和限制，不能满足的精确续航要求明确说明原因。生成原文/统计的诱导请求被拒绝。未识别或已有周报请求仍可使用原有函数调用路径，失败或超时转换为可继续对话的说明。

## 异常与交互

- 单项工具查询有时间边界，失败保留其他可用结果，返回部分完成状态。
- 数据库工具读查询使用保存点，返回错误或抛异常时回滚该查询，避免污染保存聊天记录的事务。
- 原有模型路径设置整体等待上限。取消操作继续传播，不吞掉用户停止请求。
- 客户端由应用生命周期统一复用并关闭，配置有效时在启动就绪前预热，避免逐轮初始化和首问等待。
- 聊天界面显示部分完成状态，支持原问题重试；切换新会话后忽略旧流的事件和完成状态。
- 内部 grounding 错误不直接展示给用户。无结论提示与无数据区分，保留用户可继续追问的上下文。

## 验证

最终全量后端测试：528 通过、1 跳过。前端59项测试通过，包含聊天失败重试、部分结果和旧请求隔离；类型检查、前后端 lint 及 diff 检查通过。

真实API完整开发集25/25通过、保留集3/3通过。最终报告分别为 `artifacts/e2e/product-verified-development.json` 和 `artifacts/e2e/product-final-holdout.json`。场景覆盖原始复合提问、错别字、续航、差评/好评原文、统计、趋势、产品切换、目录、比较、未知产品、未来时间、诱导编造及普通对话。

最后一次回放曾被Windows临时文件锁打断报告写入，24轮业务检查均通过但不计整套通过；增加保留旧JSON的原子替换重试后，重新执行完整25轮通过。报告写入重试另有故障注入测试通过。

语义核对材料为 `artifacts/e2e/product-development-review.json` 和 `artifacts/e2e/product-holdout-review.json`。逐字原文与已知冲突型号审计结果为 `artifacts/e2e/product-quote-audit.json`，28轮未发现引用原文不匹配或重新引用DELTA Max型号的情况。另复核了趋势的ISO周/日期、提及率分母、差评方面数量、好评原话、续航工况和待核实情绪标签展示。这是当前数据和问题集的验收，不是对任意未来输入及外部服务可用性的保证。

预热验证报告为 `artifacts/e2e/reliable-warm-start.json`。本机本轮记录的首条复合请求约0.41秒，评论数量约0.01秒，续航约0.34秒；不包含应用启动时间，不代表外部服务的延迟保证。

原始数据中存在型号和情绪标签的待复核项，产品通过排除不可靠体验引用、标记不一致及明示统计口径处理。新增产品别名或复杂时间表达仍需扩充回归；不确定时应澄清，不猜测。
